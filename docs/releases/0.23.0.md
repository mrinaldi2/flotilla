# Flotilla 0.23.0: release notes

## What's new

**The team on demand** ([team.md](../team.md)). A project's lead is always
on; the rest of the team sleeps when idle and wakes when work arrives.

- **Presence:** each bot is Always on or On demand. Upgrading makes every bot
  on demand except each project's lead.
- **Sleep and wake:** an on-demand bot sleeps after 10 idle minutes and keeps
  its memory and conversation. It wakes on a card, a task, a message, a
  review, a routine, or when you open its chat or press **Wake now**.
- **Running cap:** at most 6 bots run at once on a computer. Work for the
  rest waits in a queue that keeps the board's priority order; only an
  urgent (P0) bug jumps ahead. The team view shows "4 of 6 running · 2
  waiting".
- **Roles:** Product and Architect join the board roles. The lead assigns
  cards to a role, and Flotilla wakes whoever holds it. Workers spawned from
  a role copy its member's instructions and model, for extra parallel hands.
- **Browser only where needed:** a bot gets its own browser only as Tester or
  UX reviewer.
- **On the phone (0.11.0):** Asleep, Wake, Always on / On demand, the running
  counter and Assign to role.

On the owner's Mac, with the PhD project's 13 bots, the team went from about
**7.3 GB** of memory (13 Claude Code sessions and 43 browser processes) to
**0.44 GB** with only the lead awake. Waking a bot and putting it back to
sleep takes about 5 seconds.

**Lighter checkouts** ([checkouts.md](../checkouts.md)). For a project with
a repository:

- one shared mirror of the repository per project;
- a worktree per card, made by Flotilla (`worktree_for`), sparse when asked,
  and removed when the card's pull request merges;
- read-only repository tools for bots that don't write code (`repo_file`,
  `repo_diff`, `repo_log`, `repo_grep`);
- shared build caches: `sccache` for Rust when installed, one pnpm store, and
  warm `node_modules` seeds copied with APFS `clonefile`;
- a disk budget per project.

## Upgrading

- **Database:** the daemon backs up the database and migrates it from schema
  75 to 77: each bot's presence (076) and each project's disk budget (077).
- **Bots:** after the upgrade only each project's lead runs. The others are
  Asleep, and wake on their next piece of work. Switch any bot back to Always
  on in its settings.
- **Older apps:** an app from before 0.23 shows an asleep bot as stopped, and
  hides the new controls; a linked computer from before 0.23 is sent stopped
  for an asleep bot.

## Rolling back

Reinstall 0.22.0. The database stays at schema 77; 0.22 ignores the two new
columns. To return to the exact 0.22 data, restore the `pre-migration-…`
backup under `~/.flotilla/backups`.
